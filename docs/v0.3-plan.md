# SLUMDUNK TYCOON V0.3 개발 계획

브랜치: `v0.3-dev` · 기준 버전: 태그 `v0.2` (Render 운영 버전, `main`)

## 확정된 기획 (Stage 1)

| 항목 | 내용 |
| --- | --- |
| 화면 | 모바일 세로형, 스크롤 없는 한 화면 플레이 |
| 제한시간 | 5분 |
| 메뉴 | 저스트치즈버거 전용 |
| 주문 템포 | 시간이 지날수록 주문 간격이 조금씩 짧아짐 |
| 동시 주문 | 초반 1개 → 후반 3~4개 |
| 패티 조리 | 타이밍 터치. 등급 PERFECT / GOOD / MISS |
| 조립 | 재료를 순서대로 터치. 드래그 없음 |
| 실수 수정 | 취소 버튼으로 마지막 재료 제거 |
| 안내 | 레시피 표시 + 다음 재료 강조 |
| 완성/판매 | 마지막 재료를 넣으면 자동 완성 + 자동 서빙 ('버거 완성'·'손님에게 판매' 버튼 제거) |
| 보상 | 빠른 서빙 시 자동 팁 |
| 연출 | 동전, 효과음, 손님 반응 애니메이션 |
| 난이도 원칙 | 주문 우선순위 선택 없음. 머리 쓰지 않고 편하게 즐기는 캐주얼 |

## 단계

1. **완료** — `v0.2` 태그, `v0.3-dev` 브랜치, HTML/CSS/JS 파일 분리, 회귀 테스트(`tests/regression.js`).
2. 로직/화면 분리: 게임 규칙을 화면 코드에서 떼어내 순수 로직 모듈로 만든다. V0.2 회귀 테스트 통과 유지.
3. 기획 반영 (디자인 레퍼런스 없이 가능한 범위):
   - 주문 큐: 동시 주문 1→3~4개, 시간 경과에 따른 주문 간격 단축. 처리 순서는 자동(가장 오래된 주문부터), 플레이어 선택 없음.
   - 조리 등급: PERFECT / GOOD / MISS 구간 정의 (현재 38~76% 성공 구간을 기준으로 세분화).
   - 자동 완성·자동 서빙, '버거 완성'·'판매' 버튼 제거.
   - 빠른 서빙 팁: 주문 대기 시간 기준.
   - 다음 재료 강조, 레시피 상시 표시.
4. 그래픽·레이아웃: 디자인 레퍼런스와 신규 에셋 수령 후 확정. 한 화면 구역 배치(손님 / 그릴 / 조립대 / 재료 트레이), 360×640 · 390×844 · 430×932에서 스크롤 없음 확인.
5. 연출: 동전, 효과음, 손님 반응 애니메이션.
6. 미리보기 배포(별도 Static Site, `v0.3-dev` 연결) → 승인 후 `main` 병합.

## 결정이 필요한 수치

- PERFECT / GOOD / MISS 구간과 등급별 보상 차이
- 주문 간격 곡선(시작·종료 간격), 동시 주문 3개/4개 전환 시점
- 팁 금액과 '빠른 서빙' 기준 시간
- 목표 매출 350,000원 유지 여부 (동시 주문·팁이 들어가면 달성 난이도가 바뀜)

## V0.2에서 발견된 기존 동작 (현재 그대로 보존, V0.3에서 처리)

- 패티보다 다른 재료를 먼저 쌓으면, 패티를 구운 뒤에도 '소고기 패티' 버튼이 잠겨 있다. 굽기 처리 후 화면 갱신이 없어서이며, 취소 버튼을 눌러야 풀린다.
- 게임 종료 시 화면 갱신이 없어 다음 재료 버튼이 활성 상태로 남는다. 결과 화면이 전체를 덮어 실제 조작은 불가.

## 배포 시 주의

- `css/`, `js/` 파일이 생겼으므로 운영 배포 전에 캐시 정책(Render Headers 또는 파일명 버전 표기)을 정해야 한다. 현재 `index.html`만 no-cache.
